# Decisions

Choices made where the spec was silent or ambiguous.

- **LLM provider.** Model-agnostic: `AI_PROVIDER` picks Anthropic (official SDK, `lib/llm-anthropic.ts`), OpenAI or Meta Llama (both through the `openai` SDK, `lib/llm-openai.ts`). The app only calls `lib/llm.ts`. With no `AI_PROVIDER`, the first key that is set wins. For Llama the model is verified lazily with `GET {LLAMA_BASE_URL}models`; if `LLAMA_MODEL` is missing it falls back to the first "maverick" / "llama" id. Nothing runs at process start, so the app boots without a key.
- **Structured output.** `extractStructured` tries each provider's native JSON-schema output, then forced tool calling (OpenAI and Llama), then plain prompting. A 400/404/422 moves to the next mode; validation failures retry up to 2 times with the Zod error sent back to the model. On Llama, temperature is 0 for extraction and 0.1 for chat; OpenAI and Claude use their defaults. Claude runs with server-side refusal fallbacks and its content blocks are replayed unchanged between tool turns.
- **Chat streaming.** Each model turn is streamed token by token. If a reply starts with `{` or a code fence while tools are enabled, it is buffered, because Llama sometimes writes a tool call as JSON text; it is then parsed as a tool call (`parseTextToolCall`).
- **Chat history.** The client folds tool results (including product and variant ids) into the assistant messages it sends back, so the agent still knows the ids on later turns without server-side sessions.
- **Search.** The catalog has at most 20 products, so `search_products` filters in memory (case-insensitive substring match, same behaviour as ILIKE) with a small synonym map (t-shirt/tee/remera, hoodie/buzo/sweatshirt, cap/gorra, bag/tote). Filters apply to in-stock variants. Text fallback to filter-only results happens only when the query matches nothing in the whole catalog.
- **MCP route.** `/api/stores/[slug]/mcp` works with the SDK's `WebStandardStreamableHTTPServerTransport` (stateless, JSON responses), so no `/api/mcp?store=` fallback was needed. CORS is open so browser-based MCP clients can connect.
- **Slug.** Derived at `POST /api/stores` from the page `<title>` (first segment) with a quick 5 s fetch, falling back to the hostname. The final store name from the AI replaces `name` but the slug never changes.
- **Ingestion.** Runs in-process after the response (fire and forget), which is fine on a long-running Node server like Render. SSE polls `ingestion_events` every 500 ms and closes when the store is `ready` or `failed`.
- **Visitor AI keys.** The server key is optional. A visitor can paste their own Claude, OpenAI or Llama key in the UI; it lives in `localStorage`, travels as `x-ai-provider` / `x-ai-key` headers and is applied with `AsyncLocalStorage` for that request only, which also covers the ingestion it starts in the background. It is never stored or logged. Without any key, the demo button uses `/mock/lumen?jsonld=1` and the Playground explains how to continue (own key, an MCP client, or the recorded run).
- **No-AI fallbacks.** Without an AI provider key, Shopify and JSON-LD ingestion still work, and the store name/description come from `<title>` and the meta description. The plain mock (no JSON-LD) needs the AI and fails with a clear message. `/mock/lumen?jsonld=1` propagates the flag to product links so the structured-data path can be tested end to end.
- **Extra columns.** `products.original_price` / `original_currency` (to show the ARS price next to USD) and `stores.error_message` (to show a clear failure reason).
- **Orders.** The order UUID is generated before calling PayPal so it can be sent as `custom_id`; the PayPal `PayPal-Request-Id` header is derived from it so retries are idempotent. Capture is idempotent in two ways: PAID orders are never re-captured, and PayPal's `ORDER_ALREADY_CAPTURED` is handled by reading the order. A capture error only marks the order FAILED on a 422 (declined), not on transient errors.
- **PayPal button.** Restricted to the PayPal funding source (no card button) to match the demo.
- **Payee.** The payee email is stored per store and never returned by the public API.
- **UI kit.** Tailwind v4 with a handful of hand-written components instead of the shadcn CLI, to keep the dependency surface small. Fonts come from the `geist` package so builds do not need network access to Google Fonts.
- **Mock store isolation.** `app/(main)` and `app/(mock)` are separate route groups with their own root layouts, so Lumen shares no layout or CSS with Vitrina.
- **Security.** URLs entered by users are fetched server-side without an SSRF allow-list (localhost must stay reachable for the mock store). Acceptable for a sandbox hackathon demo; add a block-list before any real use.
- **TypeScript 5.9.** TypeScript 7 is not yet supported by typescript-eslint, so `pnpm lint` would not run.
